System Design Document · v0.1

Multi-Agent
Software Development Engine

A system where six specialized AI agents collaborate to transform a plain English product idea into a complete development package — with human approval at every critical decision point.

Status: Pre-development · Design phase

What It Does

A user types "Build a subscription tracking app". The system kicks off an orchestrated pipeline of AI agents — each with a focused role — that produce requirements, architecture, database schema, API specifications, implementation tasks, and a test plan. The user approves or corrects the output at two checkpoints before work proceeds. Everything is tracked: token usage, cost, latency, and output quality.

The Workflow Pipeline

User Input
"Build a subscription tracking app" — natural language, no structure required.
PM Agent — Requirements Gathering
Extracts functional requirements, user stories, acceptance criteria, out-of-scope items, and non-functional requirements from the user's description.
→ requirements.md
⏸ Human Approval Gate #1
User reviews the requirements document. Can edit, add constraints, or reject and restart. Agent does not proceed until approved.
Architect Agent — System Design
Designs system architecture, selects tech stack, produces database schema, and maps the API surface — grounded in approved requirements.
→ architecture.md · schema.sql · api-surface.md
⏸ Human Approval Gate #2
User reviews the architecture. Can swap tech stack choices, adjust schema, or flag design concerns before parallel work begins.
↓ Parallel Execution — all three run simultaneously
Backend Agent
Full OpenAPI spec, DB migrations, implementation task backlog with estimates.
→ openapi.yaml · tasks.md
Frontend Agent
Component hierarchy, page list, routing plan, state management approach.
→ frontend-spec.md
QA Agent
Test cases, acceptance criteria checklist, edge cases, testing strategy by layer.
→ test-plan.md
Reviewer Agent — Cross-Review
Reads all agent outputs. Flags inconsistencies between spec layers, validates completeness against requirements, assigns a quality score.
→ review-report.md · quality_score: 0–100
Final Development Package — Delivered
All artifacts bundled. Workflow summary with cost, token usage, and per-agent latency attached.
→ workflow-summary.json · all artifacts

Key Features

MEM

Memory Layer

Agents remember past projects and decisions. New projects benefit from accumulated context — preferred patterns, past mistakes, user preferences.

PostgreSQL — structured project history
ChromaDB — vector embeddings of decisions
Injected into each agent's system prompt
User can tag decisions to persist
HIL

Human-in-the-Loop

Two mandatory approval gates. The system pauses and waits. Users can edit, annotate, and explicitly approve before the pipeline resumes.

Gate #1 — after requirements
Gate #2 — after architecture
Approval state stored in DB
Rejection triggers targeted re-run
OBS

Observability

Every agent run is instrumented. Track where time and money go across each workflow, and compare across projects over time.

Per-agent: tokens in/out, cost, latency
Per-workflow: total cost, wall-clock time
Success / failure rate per agent
Dashboard view (Streamlit or simple HTML)
EVAL

Evaluation System

A fixed benchmark suite of 3 reference tasks lets you measure quality and cost objectively — across code changes, model swaps, or prompt updates.

Benchmark: CRM · Expense Tracker · Blog
Scores: completeness, arch quality, cost
Stored in DB, comparable over time
Run with one command: python eval.py
